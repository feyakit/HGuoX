# HGuoX 3.0.19

> 两件事：**底栏不再压系统手势条**（安全区真正生效），**首页冷启动从 45 秒压到十几秒**（上游停用「信封」接口后的直连兜底）。

## 一、底栏压手势条（P0 修复）

3.0.18 里底栏虽然改小了，但小米九实测底边**压进系统手势区 22px**——原因是 `--sab` 一直是 0。

根因：安全区桥只在「inset 变化监听」里写入，**启动那次回调不触发**，所以从一开始就是空值。

修法（三道保险 + 可观测日志）：
1. Kotlin 侧改成 `Plugin.load` 时注册，并在 `onActivityResumed` 与首次 `setOnApplyWindowInsetsListener` 各写一次
2. 取 `WindowInsets` 底部最大值（`navigationBars` / `mandatorySystemGestures` / `systemGestures`）÷ density 写入 `--sab`
3. 监听导航模式切换（手势 ↔ 三键）、横竖屏旋转、系统设置变化，自动重算，**不需要重启 App**
4. `debug.log` 输出 `[safearea] inset_px=44 css=16`，以后真机可直接核对

## 二、首页冷启动 45 秒 → 十几秒

上游 2026-11-25 停用了 `POST /api/edge/request`（返回 503「接口已停用」），而我们的业务请求都走它。main 之前没有兜底，只能靠镜像重试硬扛，冷启动实测要 **45 秒**。

这批修复：

| 内容 | 效果 |
|---|---|
| 认出「接口已停用」→ 自动改**直连 REST**（`{origin}{path}` + Bearer + Referer） | 首次请求就能通，不再等镜像轮换 |
| 单次逻辑请求**总预算 12 秒**（原为 20s × 3 重试 = 60s） | 黑洞丢包时不再挂满一分钟 |
| 503 也走错误分支（否则判定永远触发不到） | 兜底路径真正可达 |
| 换线**不吃旧缓存**，发布页与探活并行 | 候选里不会全是已被墙的旧镜像 |
| 探活在预算内重试 + 直连探测兜底 | 不再因一次 TLS 概率性阻断把活镜像判死 |
| 所有域名**默认先走 DoH** | 镜像域同样被污染，DoH 先取正确 IP |
| 网络诊断报告写入「系统解析 / DoH 解析 / 实际连接」三行 IP | 以后现场可判 |
| 手动选定的线路失败时**不自动跳**，文案说明原因 | 尊重用户选择 |
| hero 补详情改两轮预算（6s + 8s） | 不再只剩一张卡 |

## 已知限制

- 主域 `huangguoai.com` 连阿里 DoH 都返回劫持地址，所以 DoH 对主域无效；真正救场的是「镜像族 + 直连 REST 兜底」
- 手动线路失败的「不自动跳」只有浏览器 harness 逻辑验证，真机上无法造出「死的手动线路」
- 收藏等需登录的功能，游客态只验了展示
