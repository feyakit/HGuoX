# HGuoX 3.0.20

> 三个问题：**冷启动十几秒 → 1 秒出头**、**切下一集不再重复加载**、**首屏不再把同一批请求发两遍**。

## 一、冷启动：16.7s → 1.2–1.6s

3.0.19 在小米九上冷启动实测 12.4 / 24.4 / 失败 / 19.2 / 14.2 秒（中位 16.7s，5 次里 1 次停在错误页不自愈）。骨架 1.4 秒就出来了，十几秒全花在数据拉取上。

四条改法：

| 改法 | 说明 |
|---|---|
| **上次成功线路优先** | 24 小时内成功过的线路启动即用，零探活；不是它则只探 2.5 秒，**完全不碰被墙的主域**；它也不通才走完整探测流程 |
| **首屏请求并行 + 分阶段** | 首屏只依赖的请求并行发出，其余（hero 详情补全、非首屏榜位）等内容出现后再补 |
| **错误页自动重试** | 三次，退避 1s / 3s / 7s，每次换一条候选线路；三次都失败才展示错误页 |
| **失败即换线重试** | 单次请求失败（DNS/TLS/RST/超时）后在同一次加载流程内换线重试，不把失败往上抛 |

实测（小米九，家里对上游域名有 DNS 劫持 + TLS 阻断的网络）：**首屏内容 1.617 / 1.323 / 1.201 秒，0 次重试、0 次换线、0 条错误**。

## 二、下一集加载两次

现象：切集时「转圈 → 停顿 → 又转圈」。

根因：预取那条**已经取到了播放地址**，切集那一刻取址 effect 带 `force=true` 把在途请求顶掉重取（`EpisodePlayer.tsx:1034` → `playRequests.current.delete(key)`）。真实 CDN 每次 token 不同，第二次地址覆盖后 `<video>` 按 `[src]` 重挂，用户就看到第二次转圈。

改法：同一 `(视频, 集, 线路代次)` 的在途请求合并复用，`force` 不再顶掉已完成的预取；预取与播放分层不同 key。

实测（小米九连追 4 集）：`api_play` **每集恰好 1 条**。

## 三、首屏请求发两遍

现象：冷启动 21 条请求只有 12 个不同 URL；`api_feed` 每次发 2 次，8 个详情 id 每个也发 2 次。

三个原因叠在一起：

1. **启动动画收尾把整棵树卸载重挂了一次**（主因）——`LaunchAnimation.tsx:141` 根节点类型从 Fragment 变成 App，React 判定换组件，把 `AppProvider + App + Home` 整棵卸载重挂（`mount 1804ms → unmount 3931ms → mount 3933ms`），第二个 Home 实例重新发首屏请求
2. `prefetchDetails` 发出的请求没登记进 inflight，第二批又各出网一次
3. `api.ts` 的 key 与调用方 args 不一致，合并没兜住

三处都已修，并新增 `tests/firstscreen-dup` 夹具专测。
