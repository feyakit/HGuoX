# 线路策略（自动 / 手动 / 偏好）

> 3.0.0 的问题：手动选一次线会写 `hguox_auto_line=off`，等于**永久**放弃自动选线。
> 小米9 上就停在「固定线路1 = huangguoai.com」，DNS 被污染后应用直接不可用。
> 现在手动选线只是「本次优先」，自动选线一直开着，直到用户在设置里主动关。

## 两个键，两件事

| 键 | 含义 | 谁写 |
|---|---|---|
| `hguox_auto_line` | 要不要自动选线（`on` / `off`） | 只有设置页的「自动选择线路」开关 |
| `hguox_line_preferred` | 用户手动点的线路（偏好），空 = 无偏好 | 线路面板/播放页切线路面板；「恢复主站」清空 |

判定逻辑：`src/shared/network/linePolicy.ts` 的 `decideLine()`（纯函数，无 IO）。
取数与落库：`src/shared/network/autoLine.ts` 的 `pickLine()`。

## 何时切 / 何时不切

| 场景 | 偏好线路状态 | 动作 | 提示 |
|---|---|---|---|
| 启动、亮屏、恢复网络 | 无偏好 | 用后端 `line_auto` 选出的线路 | 切了就有 `hg:line` 气泡（原有行为） |
| 启动、亮屏、恢复网络 | 偏好可用（探活 ok / 可达 / 不在候选表里） | **一律用偏好**，后端选了别的也切回来 | **无** |
| 定期巡检 | 当前就是偏好，健康 | 不动 | 无 |
| 定期巡检 | 当前是别的线路，偏好不在避让窗口 | 复检偏好，通了就切回 | **无**（回切不打扰） |
| 巡检发现当前线路失败 **1 次** | — | 4s 后再看一次 | 无 |
| 当前（= 偏好）连续失败 **2 次**（探活 ×2 或请求 ×2） | 偏好失败 | 让位给后端选出的可用线路 | **「当前线路不可用，已自动切换」**（30s 内只说一次） |
| 同上，但后端也没有可用线路（`all-down`） | — | 保持原线路 | 「线路全部不可用，请检查网络或代理」（原行为） |
| 让位后 5 分钟内 | 偏好可能只是抖 | 停在替代线路，不回切 | 无 |
| 让位 5 分钟后，巡检健康 | 偏好恢复 | 静默切回偏好，并清空避让窗口 | **无** |
| 设置页关掉「自动选择线路」 | — | 完全不自动：不探活、不切换、不取消已选线路 | 开关自身的 toast |
| 关掉自动后再手动选线 | 写入偏好 | 立刻生效，偏好留着（下次开自动就用它） | 面板 toast |
| 有偏好时的「自动回切主站」（`line_try_main`） | 偏好存在 | **跳过**：主站再好也不能抢用户的线 | 无 |
| 面板里点「恢复主站」 | 清空偏好 | 按后端默认主站，完全自动 | 「已恢复主站 …」 |

## 迁移

旧版本只要手动选过线就写 `auto_line=off`，那不代表用户想关自动选线。
升级后第一次启动（`migrateLegacyAutoLine()`，在 `initAutoLine()` 最前面）：
`auto_line=off` → 写回 `on`，并落标记 `hguox_auto_line_v2=1`；之后用户在设置里关掉的 `off` 才是真的关。

## 失败计数口径

| 计数 | 增量 | 清零 | 达到 2 时 |
|---|---|---|---|
| 探活失败 `downStreak` | `line_health` 返回 `ok=false` 或抛错 | 任意一次健康 / 一次成功选线 | 触发 `pickLine(force)` |
| 请求失败 `failStreak` | 网络类命令失败（`netObserver`，`networkish` 才算） | 任意一次成功请求 | 触发 `check()` |

「连续失败」只对**当前生效线路**计数；已经让位到替代线路时，替代线路失败同样按 2 次口径处理，
但偏好仍处于避让窗口里，不会立刻回切（避免两条都抖时来回跳）。

## 线路自愈（3.0.7 起）

> 背景（小米9 / 家宽，2026-11-21 实测）：`huangguoai.com` 与 `huangguoai.pages.dev` 被 DNS 污染到
> **公网 Facebook 段**（`157.240.1.50` / `2a03:2880:…:face:b00c`），不是 127.0.0.1 —— 旧的
> 「只有私网地址才回退 DoH」判据救不到，只会干等 TCP 超时；唯一可用的发布页 `huang-guo.pages.dev`
> 拉 page + publish.js 要 2.1–7.2s（10 轮里 1 轮 >6s），6s 预算会周期性把整份镜像列表判死 →
> 自动选线零候选 → 应用完全打不开。

自愈由四层组成，**从快到慢依次兜底**，任一层拿到可用候选就往下走：

| 层 | 机制 | 实现 | 关键参数 |
|---|---|---|---|
| 1 | **DoH 优先解析** | 发布页与固定线路域名先走加密 DNS（`get_public_dns` / `DOH_FIRST_HOSTS`），失败才退回系统 DNS | 解决 DNS 污染；不再要求「解析结果是私网」才回退 |
| 2 | **发布页先到先用** | `mirrors()` 并发拉两页（page / publish.js），**第一页成功就先用**，另一页只再等 2s，不再 `join` 死等被污染的那一页 | `PAGE_TIMEOUT` 6s → **12s**；第二页宽限 **2s** |
| 3 | **镜像列表落盘兜底** | 解析出的候选写 `lines-cache.json`；两页都失败时读回并标 `stale`，**只当探活候选** | 缓存命中也要逐条真探活 |
| 4 | **内置种子候选** | 仅当发布页候选 < 3 时补位，同样逐条探活，**不通不入选** | 6 个种子 |

探活预算同步放宽：`AUTO_PROBE_TIMEOUT` 3s → **5s**（38 个候选抽样 1.13–2.75s，最慢一条已用掉 3s 预算的 92%，容易被误杀）。

### 信任边界（不变）

- 落盘缓存与内置种子**只用于切换线路、供游客浏览**：`net::apply_base` 放行 `is_cached_mirror()`，
  否则会出现「缓存里挑到了可用镜像，却报『线路不在固定线路或可信发布页清单中』」。
- **登录凭据信任边界不动**：`trusted_auth_origin()` 仍只认固定线路与可信发布页，
  落盘缓存 origin 与种子**不会**被授予携带 token 的资格（单测里直接断言：缓存 origin 可切、但不进信任集合）。

### 发布页解析规则（加固）

| 情况 | 处理 |
|---|---|
| 有 `urls` 数组 | 按数组解析（原行为） |
| 没有 `urls` 数组 | 静态扫描字符串字面量里的裸域名与 `https://host`（回退扫描） |
| 回退扫描只认 | `https://host` 形式，以及站根 `xxx.cc/` 形式 |
| 明确不认 | 注释里的裸域名、发布页域名本身、三级以上主机名拼出的子域 |

> 反例（3.0.6 之前）：发布页 JS 注释里出现的裸域名被当成镜像，选线后必然失败。

## DNS 解析：fake-IP 混合 IPv6 ULA（3.0.9，`22cca21`）

> 现象：开着 Clash / Stash / sing-box / Shadowrocket 这类 **TUN 代理**时，应用**全站请求失败**（首页、播放、登录全挂），关掉代理就正常。用户第一反应是「线路坏了」，其实是 DNS 结果被我们自己的校验整组拒了。

### 根因

TUN 模式的 fake-IP 会在系统 DNS 层同时合成两类地址：

- **fake-ipv4**：`198.18.0.0/15`（代理自己认、由它转发到真实上游）；
- **合成 IPv6 ULA**：`fdfe:dcba:9876::/48`（Clash 系）/ `fc00::/18`（其他实现），这些地址**根本不可路由**，只是为了让 AAAA 查询「有答案」。

旧实现是 `retain_allowed_when_fakeip()`：**只有集合里已经出现 fake-IP 时**才去过滤伴随的 ULA。于是下面这种最常见的组合照旧整组报错：

```
A    → 真实公网地址（没被 fake-IP 接管，比如 DoH 直连或域名在白名单里）
AAAA → fc00::/18（代理合成的 ULA，不可放行）
→ 整组校验失败 → denied_target → 所有请求失败
```

### 修法（按上游 `70d5120` 重写，不是打补丁并存）

- 新增 `pinable_addresses()`：严格模式下**先过滤掉 `allowed_ip` 不为真的地址**，只把可放行地址（公网单播 + `198.18.0.0/15` + `fdfe:dcba:9876::/48`）交给连接器固定；
- 整组都不可放行时仍然报 `denied_target()`（该拒还是拒）；
- `allowed_ip` 白名单**一字未动** —— 没有为了让 fake-IP 通过而放宽私网；
- 删除 `retain_allowed_when_fakeip()`（已被 `pinable_addresses()` 覆盖）；
- 备用 DoH（`media_dns.rs`）**不经过这里**，仍保持整组严格校验（任一记录不可放行即失败）；`net.rs` 的备用解析路径行为不变；
- 错误文案保留我们自己的版本（带「我的 → 设置」提示），不采用上游的缩短版。

### 组合对照

| DNS 返回 | 旧行为 | 3.0.9 |
|---|---|---|
| 只有 fake-ipv4（`198.18.x.x`） | 过滤后保留 | 保留 |
| fake-ipv4 + 合成 ULA（`fdfe:dcba:…`） | 过滤后保留 | 保留 |
| **真实公网 A + `fc00::/18` 的 AAAA** | **整组拒绝**（全站失败） | 只保留公网 A，连接照常 |
| 公网 + 私网混合（`1.1.1.1` + `192.168.1.1`） | 视是否已出现 fake-IP 而定 | 只保留公网地址（与上游语义一致） |
| 整组都不可放行 | `denied_target()` | `denied_target()`（不变） |

### 验证

- 改动范围：`src-tauri/src/network_policy.rs`（+67 / −34），无新依赖；
- 单测搬入上游 `fakeip_mixed_answers_keep_only_the_pinnable_addresses`，原有 `dualstack_fakeip_strips_unroutable_companion_aaaa` 改为调用新函数；
- 提这个改动时本机没有 cargo/rustc，编译与 `cargo test` 由 CI 完成；
- 真机侧：**没有做「开/关 Clash TUN」的对照实验**，这条目前靠单测覆盖（用例直接构造「公网 A + ULA AAAA」的解析结果）；哪台机子上装了 TUN 代理就能顺手补一次。

> **边界提醒**：这条只解决「解析结果里混进不可放行的伴随地址」。真正的 DNS 污染（解析到公网 Facebook 段）仍由上一节的 DoH 优先解析处理；SNI 层阻断（TLS ClientHello 被 RST）谁也绕不过，见 `docs/已知问题.md` 第 1 条。
