# 上游同步评估（上游原项目 → 本仓）

基线：`git log main..upstream/main`，当前 `main` = `edcdc20`（v3.0.9），`upstream/main` = `848a199`（2.2.6 + tv-2.2.4 收尾）。
口径：**只看功能修复，UI/文案/目录重构一律不动**（用户定的）；与我们自己的实现冲突时以我们为准，并在提交里写明适配点。

> 上一版这份文档记的基线是 `a7d22db`（上游 v2.2.0 收尾）、落后 **38** 个提交。上游随后发了 2.2.1 → 2.2.6，所以重算后是 **135**（含 merge）/ **123**（非 merge）。下面所有数字都按 123 个非 merge 提交逐条对过。
>
> 另外，「我们的树在上游模块化重构之前分叉、Rust 提交不能 cherry-pick」这句只对一半了：**前端目录已经对齐上游**（`ebd987a`，`src/app` + `src/features` + `src/shared`，产物字节级不变），所以前端提交可以按文件对照搬；**Rust 侧仍是扁平文件**（`api.rs` / `net.rs` / `lines.rs` / `media.rs`，上游已拆成 `api/ net/ lines/` 模块），Rust 提交仍然只能按行为手搬。
