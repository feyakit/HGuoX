## 一、产品 / 上游限制（我们改不了）

### 1. 国内网络对主站存在 SNI 阻断

**现象**：`huangguoai.com` 在国内家宽/移动网络下直连不通（TLS 握手被丢），只能走镜像；
镜像发布页本身也常被 DNS 污染到公网 Facebook 段（`157.240.1.50` / `2a03:2880:…:face:b00c`）。

**根因**：网络层的 SNI 阻断 + DNS 污染，不是应用能绕的；应用能做的是**换路**。

**3.0.7 已经做的**：线路自愈四层兜底（DoH 优先解析 / 发布页先到先用 / 镜像列表落盘 / 内置种子），
详见 `docs/线路策略.md` 的「线路自愈」一节。应用侧做到「有一条镜像通就能用」。

**为何不硬修**：再往上就得上自定义 SNI、ECH 或内置代理，属于对抗网络审查，本项目不做。

**何时再修**：不修；如果主站长期不可直连，就把「默认线路 = 镜像」写进发布说明，别让用户以为是自己网坏了。

### 2. 上游没有分辨率分档，「画质」只能高清 / 标准

**现象**：播放页的画质胶囊只有「高清 / 标准」两档，没有 720p / 1080p 这种选择；
多数剧只有一条流，此时胶囊置灰不可点。

**根因**：`api_play` 只下发 `streams.main` 与 `streams.hevc` 两条地址，**没有分辨率/码率字段**，
前端无法凭空造出分档；硬做一个「1080p」按钮就是假控件。

**为何不硬修**：等上游接口给出多档位（或给出 `width/height/bitrate`）再谈。

**何时再修**：上游 `api_play` 增加多档 streams 时。

### 3. 评论没有删除接口

**现象**：自己发出的评论无法撤回、无法删除，只能等站点侧处理。

**根因**：应用与官网都没有删除接口（`api_comments` 只有读 + 发）。

**为何不硬修**：前端删除只能删本地，会造成「我这没了、别人还看得见」的假象，比不做更糟。

**何时再修**：上游提供 `DELETE /api/comments/{id}` 或官网页面出现删除入口时。

### 4. MIUI 会把应用冻结成 `enabled=3`

**现象**：小米九等 MIUI 机型上，应用可能被系统冻结（`pm list packages -d` 里出现），
点图标无反应；`pm enable` 只能顶几秒，之后又被冻回去。

**根因**：MIUI 的省电/后台管控对 sideload 应用更激进，冻结状态不是应用自己能改的。

**为何不硬修**：应用内没有能改系统包状态的权限（也不该有）。

**绕法**：`adb install -r <apk>` 重装一次即可恢复；长期自用建议在系统设置里关掉该应用的「省电策略」。
后续如果做自更新，重装路径天然会解冻，可以顺带写进更新说明。

### 6. `scripts/test-playback.mjs` 本地默认跑不起来

**现象**：`npx playwright install` 提示缺浏览器，用例 0 passed / 1 failed。

**根因**：它用 `playwright-core` 的 `chromium.launch()`，没有 `executablePath` 就找 Playwright 自带的浏览器；
容器里只有 `/opt/data/home/.cache/ms-playwright/chromium-*/chrome-linux/chrome`。

**为何暂时不修**：不是代码问题，是环境里没装 Playwright 的浏览器包；CI 里正常。

**本地怎么跑**：`BROWSER_EXECUTABLE=~/.cache/ms-playwright/chromium-*/chrome-linux/chrome node scripts/test-playback.mjs`
（其它 `test-*` 用例都读这个环境变量，只有它还只认 `--browser-executable`）。

**何时再修**：下次动播放相关代码时顺手把缺省值改成读 `BROWSER_EXECUTABLE`。

### 7. `scripts/test-round-review.mjs` 只在 GitHub Actions 里跑

**现象**：本地跑直接报 `Run this review only in GitHub Actions.`

**根因**：它是 CI 里的聚合回归（要 clone 基线再跑一整套），本地跑没有意义。

**这一轮的处理**：改成打印 `SKIP: …` 并 `exit 0`（CI 里行为不变），
否则「本地把所有 test-* 跑一遍」永远会多一条红，掩盖真正的问题。

**何时再修**：不需要；如果以后要本地复现，给它加一个 `--baseline <sha>` 参数即可。

### 8. iOS 图标矢量源不在仓库

**现象**：`scripts/test-ios-icons.mjs` 以前直接 ENOENT。

**根因**：上游同步之后仓库只带生成好的 PNG，没有 `src-tauri/icons/ios/source.svg`；
`scripts/generate-ios-icons.mjs` 自己已经写了「缺源就跳过并沿用已跟踪 PNG」。

**这一轮的处理**：用例改成「有源就校验源、没源就打 SKIP 并继续校验 18 个槽位的 PNG + 构建钩子」，
与构建脚本行为对齐。

**何时再修**：如果决定把矢量源重新入库，再把那两条断言无条件打开。
注意：入库的 SVG 必须**方形、无 `rx`/`stroke`、内容包在 `<g>` 里**，否则五平台构建会一起挂。

### 9. 上游 API 不接受任何未知查询参数（所以没有 URL cache-buster）

**现象**：想给「刷新」加一个 `_t=<ms>` 之类的 cache-buster 时，请求直接 `400 {"status":0,"msg":"请求参数无效"}`。

**实测**（2026-11-21）：

```
GET /api/videos?page=1&size=21            → 200，cache-control: private, no-store
GET /api/videos?page=1&size=21&_t=123     → 400 请求参数无效
GET ...&t=123 / &r=123 / &v=123           → 全部 400
间隔 3s 两次请求                           → 响应字节完全一致（同 sha256、首条 id 相同）
```

**结论**：上游本来就 `no-store`，URL 层没有缓存可绕；硬加参数只会让刷新失败。
所以「绕过缓存」只做在应用层（`call(cmd, args, force)` 跳过内存读缓存与在途合并），
**不要**再往上游 URL 拼时间戳。

**何时再修**：上游若开始用 CDN 缓存并接受忽略型参数，再考虑 URL 级 cache-buster。

## 三、测试覆盖与取证手段的缺口（3.0.9 新增记录）

> 这三条不是产品缺陷，是「我们知道它现在没被验证到 / 验证手段够不着」。写在这里是为了以后别把它们当成「已验证」。

### 10. iOS 拿不到 DOM 级取证

**现象**：iOS 上的结论只能靠真机目视 + 二分实验，拿不到 `getBoundingClientRect`、`img` 重建次数、逐帧亮度这类数字。3.0.9 的吃瓜详情闪屏就是按这个条件定案的（三版二分 + 目视）。

**根因**：`ios_webkit_debug_proxy` 不支持 iOS 17+ 的 `remoted` 通道，Safari 远程调试只对桌面 Safari + Safari 技术预览开放；我们不引入越狱或私有协议。

**为何暂时不修**：属工具链限制，应用侧无从下手。安卓侧有 CDP 可取证，iOS 没有对等能力。

**何时再修**：苹果开放 `remoted`（或出现可用的开源实现）时，再给 iOS 补一套与安卓对等的 DOM 断言。

### 11. 吃瓜详情只覆盖了「带内嵌视频」的帖子

**现象**：3.0.9 的两条闪屏修复（安卓 DOM 重建 `56b6c4e` / `8381a90`，iOS 滚动合成 `9d41c6f`）都是在**带内嵌播放器**的帖子上验的。纯「单张长图」和「纯多图、没有视频」这两类帖子没有独立验过——而这两类恰恰没有播放器每帧写 `--fill` 的触发源。

**根因**：该版本吃瓜详情几乎每篇都带内嵌视频，真机上翻不到稳定的纯图样本。

**为何暂时不修**：修复本身是「不再重写 innerHTML」+「删掉一个滚动属性」，对纯图帖子只可能更好；但没有样本就不能声称验过。

**何时再修**：找到（或构造）纯单长图 / 纯多图帖子后，各跑一次滚动重建计数（安卓 `<img>` 增删次数应为 0）与 iOS 目视。

### 12. 收藏多选只做收藏页，历史页没有

**现象**：长按进入多选、批量取消收藏，只在「我的 › 收藏」可用（短剧 / 吃瓜两个 tab 各自独立）；「观看历史」页只有一键**清空全部**，没有多选，也没有单条删除。

**现状细节**：「全选」选的是**当前 Tab 的全量 id**（含尚未滚到底、没上屏的分页），移除时逐 id 处理、不依赖卡片是否已渲染；「已选 N 项」按选中的 id 计数，所以数字可能大于当前屏幕上的卡片数。选择进行中会**关闭左右滑切 tab**（误滑一下就把选好的项丢了）。

**为何暂时不修**：上游 #168 只做到收藏页，历史页的多选要另外设计「清空 / 按剧聚合」，且历史条目的删除语义（删一条还是删这部）还没定。

**何时再修**：产品先定历史页的删除粒度；定完按 #168 的实现复用即可。
