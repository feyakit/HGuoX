## P0：iOS 吃瓜页整页闪（**已定位并修复**，2026-11-22）

**结论**：元凶是 `-webkit-overflow-scrolling: touch`（`src/index.css` 的 `.scroll-y`、`src/styles/shelf.css` 的 `.hg-hero-track` 各一处）。删除即可，**零视觉差异**。

**因果链**：该属性把滚动容器交给 UIKit 的 `UIScrollView` 做异步分块栅格化；当同一页面上还存在 `position: fixed` 浮层（帖子详情页底部互动条）与 `backdrop-filter` 兄弟节点（次级页顶栏）时，WebKit 会在滚动过程中丢弃并重建滚动层的栅格块，表现就是整页在明暗两档之间**台阶式**来回跳（「丢块再补」）。iOS 13+ 的滚动容器本来就由 UIKit 统一接管，这行是冗余声明。上游 HGhubX 全仓库 **0 处**使用该属性 —— 这也解释了「上游同一篇帖子、同一手势不闪」。

**判定过程**（iPhone 真机，同一篇吃瓜帖、同一手势「按住下滑不松手」）：

| 包 | 内容 | 结果 |
|---|---|---|
| A | 三处全删（`-webkit-overflow-scrolling`、`contain: paint`、顶栏 `backdrop-filter`） | **不闪** |
| B | 在 A 上恢复顶栏 `backdrop-filter` | **不闪** → backdrop-filter 无罪 |
| C | 在 B 上再恢复 `contain: paint` | **不闪** → contain: paint 无罪 |
| 正式修复 | 只删 `-webkit-overflow-scrolling`（= C 的等价体） | 定案 |

**旁证**：Chromium 393×852 @dpr2.75（小米9 UA）对详情页顶部/正文/底部三个位置做逐像素比对，基线与修复版 **PNG md5 完全相同（0 像素差异）**；构建产物的 `index-*.css` 除「两处属性删除 + 由此变空的 `.scroll-y{}` 被压缩器丢弃」外**逐字节相同**。Chromium 不支持该属性（读数恒为空），所以这一条只能靠 iOS 真机验收 —— 已经验过。

**历史记录（定位前的观测与排除项，保留备查）**：

**现象**：iPhone 上进入「吃瓜」页上下滚动时，整页（不只图片）在明暗之间反复跳，肉眼即"闪"。用户原话：「整个吃瓜页面都在闪」「往下滑了第一张还在闪」。

**量化证据**（用户录屏 `/opt/data/attachments/753.mov`，448×960 / 12.47s / 25fps，拆成 187 帧 @15fps）：

| 帧段 | 整屏平均亮度（0–255） |
|---|---|
| 12–15 | 23.5 / 23.8 / 23.6 / 23.4 |
| 16–19 | **55.1** / 23.7 / 23.9 / **54.3** |
| 49–60 | 54.3 / 53.0 / 23.6 / 23.6 / **54.8** / 23.6 / **54.4** / 23.9 / **53.9** |
| 70–86 | 恒定 **53.42**（整屏停在骨架态约 1 秒） |

即整页在 ~23 与 ~54 之间**台阶式来回跳**，不是渐变。

**已排查（都不成立或无法复现）**：
- 图片重挂载：`MutationObserver` 监听 14 张封面、滚动 6 段，`childList` / `src` / `class` / `style` 变化 **0 条**；
- `useFadeMount` / `IntersectionObserver` 重复触发：吃瓜页未使用；
- `img` 的 `opacity` 反复从 0 起：`hg-img-ready` 加上后不再移除；
- `content-visibility`：项目内未使用；
- Chromium 393×851、Playwright **WebKit** + iPhone UA + dpr3 各跑一次滚动 12 帧，整页平均亮度 52.0 → 49.5 **单调变化，无跳变**；
- 正文 HTML / 图片重挂载（云机 CDP：222 次 `img` 增删 → 0）：安卓侧根因，iOS 侧不成立。

**此前的加固（`b426c82`、`6d251b4`，均保留）**：删 `.ios-image` 的 `translateZ(0)`/`backface-visibility`；`.shimmer` 改静态深色骨架；图片 `onError` 重试上限 2 次；滚动期 `.is-scrolling` 闸门。这些没有消除现象，但帧时间确有改善。

**相关文件**：`src/index.css`（`.scroll-y` 注释处）、`src/styles/shelf.css`（`.hg-hero-track` 注释处）、`src/scrollFx.ts`。

## 已知限制（不是 bug，改不了）

| 项 | 说明 |
|---|---|
| 画质无法分档 | 上游 `api_play` 只返回 `streams.main` / `streams.hevc` 两条流，没有分辨率/码率字段。当前 `preferHevc: true` 默认走 HEVC，失败自动回退。 |
| 评论不能删除 | 应用与官网都没有删除接口；账号上那条 `139699` 停留在 `pending` 审核态。 |
| 主站 SNI 阻断 | 国内对 `huangguoai.com` 是 TLS ClientHello 被 RST（不只是 DNS 污染），干净 DoH 拿到真 IP 也连不上。应用侧已做线路自愈（DoH 优先 / 落盘兜底 / 内置种子），但无法绕过网络层阻断。 |
| MIUI 冻结 | 小米九会把 `com.hguox.app` 冻结成 `enabled=3`，`pm enable` 只顶几秒，正解 `adb install -r` 重装同包。 |
| 小米九无 CDP | Android 11 非 root 看不到 `webview_devtools_remote` socket，所有需要 DOM 的量测只能靠截图（1 设备 px = 0.3636 CSS，dpr 2.75）。 |
