## 一、已解决（3.0.7 → 3.0.9，留记录备查）

| # | 问题 | 结论 / 根因 | 提交 |
|---|---|---|---|
| 1 | iOS 吃瓜页整页闪（明暗两档台阶式来回跳） | 元凶是 `-webkit-overflow-scrolling: touch`（`.scroll-y`、`.hg-hero-track` 各一处）：它把滚动交给 UIScrollView 做异步分块栅格化，叠加 `position: fixed` 底栏与 `backdrop-filter` 顶栏后出现「丢块再补」。删除即可，零视觉差异（iOS 真机三版二分定案；Chromium 逐像素 md5 一致） | `9d41c6f` |

| 4 | 切可信线路后掉登录 | 后端 rebase 会话、boot 决定会话，前端不再 eagerly `setUser(null)`；同一账号跨线路迁移本地历史桶 | `4c09ce6`（回归 `fa0b4c5`） |

| 9 | 清屏锁定后锁图标常驻挡画面 | 锁定时画面干净，首次点按屏幕才出现解锁钮 + 提示，2200ms 后一起收起（上游 #194） | `b35af38` |
| 10 | 横屏全屏切集时集数提示重复堆叠 / 提前弹 | 提示单槽 `playback-hint` 同 tag 原地替换；横屏等新片舞台就绪后只弹一次 | `f44d68b`、`e2a527c` |

## 二、仍未解决

### P1 某一集播放黑屏（取流问题，未定位）

**现象**：《东京牛头人》第 1 集，画面中心 RGB 均值 **0.3/255**（全黑），但控件、时间、进度条正常且时间在走；点「下一集」后同位置均值回到 **25.1/255**，画面正常。

**已排除**：播放器整体坏掉（其它集正常）、控件未渲染（同屏能读到选集/详情/域名/时间）。

**已加**：`60b8e4d` 起在 `debug.log` 里记录该集拿到的 `play` 结果（src 是否为空、HTTP 状态）。

**卡在哪**：需要复现并取 `debug.log`（小米九可用 `adb backup` 取到应用数据目录的 `debug.log`，`run-as` 不可用）。

**建议方向**：

1. 复现后看 `api_play` 返回的 `streams.main` / `streams.hevc` 是否 0 字节、4xx、或只有音轨；
2. 若上游返回 HLS 且首分片 403，检查线路/Referer；
3. 前端可加「首帧黑屏 > 2s 自动重试另一条流」的兜底，但需先确认真因再决定。

**相关文件**：`src-tauri/src/api.rs`（`api_play`）、`src/features/playback/VideoSurface.tsx`、`src/features/playback/EpisodePlayer.tsx`。

### P1 横版片源在竖屏的黑边观感未在真机验收

**现状**：`fit = portraitVideo && !rotated && !vpLandscape ? "cover" : "contain"`，即 16:9 片源在竖屏下 `contain`，上下留黑边；黑边里铺**微光效果**（`AmbientGlow`，32×18 采样画面主色）。3.0.9 已经把原来的「同一封面放大 + `blur(28px)`」虚化（`hg-lb-blur`）**整段删除**（`2d59e75`），避免两套并存。

**卡在哪**：小米九上连翻两部剧都是竖版满屏源，没找到 16:9 素材做对照；本地 Chromium mock 只能证几何，证不了观感。

**建议方向**：找一部确定 16:9 的剧（封面为横版）在真机上验：视频可见高度应 ≈221 CSS（393 宽、26% 屏高）、垂直居中、上下是微光延伸而不是硬边；`data-fx="low"` 机型确认微光降级后不出现死黑。

**相关文件**：`src/features/playback/EpisodePlayer.tsx`（`fit` 与 `ambientGlow` 入参）、`src/features/playback/AmbientGlow.tsx`、`src/styles/ambient-glow.css`。

### P2 双击 seek 精度与提示位置尚未在真机/云机闭环

**现状**：`92dca35` 起双击为三分法（左 1/3 −5s、中 1/3 播放暂停、右 1/3 +5s）；`195ae3b` 修掉「误用 snapSeek 吸附」——以前从 `t=12.4` 退 5s 被吸附到 5，实际退了 7.4s（用户看到 4s/6s）。

**卡在哪**：小米九无 CDP，读不到 `currentTime`（只能靠截图上的 `mm:ss`，1s 分辨率）；instabox 那台 `phoneqa-4c` 的补测一直没跑完。

**建议方向**：用云机（有 CDP）取 `video.currentTime`，双击左右各 3 次，判 5.0±0.3s；同时量 800ms seek 小胶囊与中央按钮、右栏的 rect 相交应为 0。

**相关文件**：`src/features/playback/playerGestures.ts`、`src/features/playback/EpisodePlayer.tsx`（`onUp` 双击分支、`seekHint` 层）。

### P2 账号相关端到端全部未验

**卡在哪**：测试账号 `ghubx` 在主站 `huangguoai.com` 与镜像站均返回「账号或密码错误」（凭据与服务端不一致），因此收藏 / 关注 / 历史 / 评论 / 点赞 / 切线路后登录态保持 都无法端到端验证。凭据存 `/opt/data/private/hguox-qa-account.json`（600），**不许出现在任何提交或截图里**。

**建议方向**：拿到可用账号后按 `v306i-b4134ae-test.md` 里的登录回归矩阵跑一遍（冷启登录、切不可信 origin 清会话后重登、连点不重复提交、失败有错误行）。

## 四、已知限制（不是 bug，改不了）

| 项 | 说明 |
|---|---|
| 画质无法分档 | 上游 `api_play` 只返回 `streams.main` / `streams.hevc` 两条流，没有分辨率/码率字段。当前 `preferHevc: true` 默认走 HEVC，失败自动回退。 |
| 评论不能删除 | 应用与官网都没有删除接口；账号上那条 `139699` 停留在 `pending` 审核态。 |
| 主站 SNI 阻断 | 国内对 `huangguoai.com` 是 TLS ClientHello 被 RST（不只是 DNS 污染），干净 DoH 拿到真 IP 也连不上。应用侧已做线路自愈（DoH 优先 / 落盘兜底 / 内置种子），但无法绕过网络层阻断。 |
| MIUI 冻结 | 小米九会把 `com.dusk.player` 冻结成 `enabled=3`，`pm enable` 只顶几秒，正解 `adb install -r` 重装同包。 |
| 小米九无 CDP | Android 11 非 root 看不到 `webview_devtools_remote` socket，所有需要 DOM 的量测只能靠截图（1 设备 px = 0.3636 CSS，dpr 2.75）。 |
| iOS 无 DOM 取证 | `ios_webkit_debug_proxy` 不支持 iOS 17+ 的 `remoted`，iOS 侧结论只能靠真机目视 + 二分（详见 `docs/已知问题.md` 第 10 条）。 |
